# DISCIPLINE — Build consistency. Not perfection.

Редакционная цифровая система для управления привычками, задачами, долгосрочными целями, аналитикой продуктивности и некарательного восстановления после пропусков.

---

## 1. Философия и архитектура

- **Build consistency. Not perfection.**
- **Evidence over motivation**: расчёт реального индекса последовательности за 14 дней (`tabular-nums`), матрица выполнения и аналитика по дням недели.
- **Recovery over punishment**: документированный пропуск с указанием объективной причины сохраняет непрерывность цикла, а встроенная **Система восстановления (Recovery System)** предлагает три практических протокола возвращения в ритм:
  1. *Протокол «Минимальный порог дня»* — временно переключает привычки на 2-минутный минимум и переносит несрочные задачи.
  2. *Протокол «Калибровка нагрузки»* — адаптирует ежедневные привычки с частыми пропусками к реалистичному недельному графику.
  3. *Протокол «Чистый горизонт задач»* — пересобирает дедлайны просроченных задач и возвращает цели в рабочий статус.

---

## 2. Реализованные функции

1. **Экран загрузки (Loading Screen)**: редакционная композиция `discipline.` с фотографией пловца в движении, плавным переходом, мгновенным входом и поддержкой `?autostart=1`.
2. **Dashboard (Сводка)**: обзор дня, 4 ключевых показателя в табличной верстке (`tabular-nums`), привычки на сегодня, приоритетные задачи, прогресс долгосрочных целей и адаптивный блок восстановления.
3. **Habits (Менеджер привычек)**: создание, редактирование, удаление (с подтверждением), фильтрация по статусам, настройка расписания (`daily`, `weekdays`, `weekly`), минимальное действие для сложных дней, интерактивная матрица за 14 дней и фиксация осознанного пропуска с причиной.
4. **Tasks (Менеджер задач)**: создание, редактирование, удаление, выполнение, приоритеты (`high`, `medium`, `low`), категории, дедлайны, привязка к целям, поиск, фильтрация и сортировка.
5. **Goals (Долгосрочные цели)**: создание целей с критерием достижения (`Definition of Done`), дедлайном, статусом, интерактивными этапами (`Milestones`) и автоматическим пересчётом прогресса.
6. **Analytics (Объективная аналитика)**: график динамики выполнения привычек за 14 дней, распределение устойчивости по дням недели (Пн–Вс), рейтинг устойчивых привычек и зон риска.
7. **Journal (Дневник рефлексии)**: ежедневные структурированные записи по 4 вопросам («Что получилось?», «Что не получилось?», «Почему?», «Что улучшить завтра?») и оценка состояния ресурса.
8. **Авторизация и хранение данных**:
   - Регистрация, вход, восстановление пароля и валидация форм с изолированным пользовательским хранилищем.
   - Облачная авторизация через Google (`Firebase Authentication`) и синхронизация с `Cloud Firestore` (`firebase-applet-config.json` + защищённые правила `firestore.rules`).
9. **Темы и локализация**:
   - Полноценные **Dark Theme** (`#0B0B0C` глубокий графит) и **Light Theme** (`#F6F4EF` архивная тёплая бумага).
   - Полная двуязычная локализация (**Русский / English**) всех экранов, форм, ошибок и системных уведомлений.

## 3. Инструкция по запуску

```bash
# 1. Установка зависимостей
npm install

# 2. Запуск в режиме разработки (порт 3000)
npm run dev

# 3. Запуск модульных тестов ядра и правил безопасности
npx --yes tsx --test src/utils/disciplineEngine.test.ts
npx --yes tsx --test firestore.rules.test.ts

# 4. Сборка production-версии
npm run build
```

---

## 4. Настройка базы данных и окружения

- Переменные окружения описаны в `.env.example` (секретные ключи не хранятся в клиентском коде).
- Конфигурация клиентского подключения к Firebase находится в `firebase-applet-config.json`, схема данных — в `firebase-blueprint.json`, а правила безопасности — в `firestore.rules`.
- При работе в локальном режиме или через быструю email-регистрацию все данные пользователя автоматически сохраняются в изолированном хранилище браузера (`localStorage` с привязкой к `uid`), а при входе через Google Firebase Auth синхронизируются с коллекциями `/users/{userId}/habits`, `/tasks`, `/goals`, `/journal`.

---

## 5. Известные ограничения

- Для работы входа через Email/Password непосредственно в облаке Firebase (помимо локального персистентного хранилища аккаунтов) администратору проекта необходимо включить провайдер Email/Password в консоли Firebase. Вход через Google и локальная регистрация/восстановление пароля работают сразу без дополнительной настройки.
- Шрифт `Tovar Kolobov` подключён в дизайн-системе первым в стеке `--font-display` с автоматическим fallback на выразительный редакционный гротеск `Syne` / `Manrope`, если локальный файл шрифта отсутствует в системе пользователя.
